## In General

Make contributions in good faith.

No AI, I reserve the right to make you explain your code, especially if it contains emoji.

If you start being annoying or make useless PRs, I will ignore you.

## In Particular

All PRs MUST only contain changes in [`/pwr/dev/`](./pwr/dev/). This is to allow me to
properly merge them into the public version of the tool.

### Issues

I'd prefer if you first create an issue for your change or assign yourself to an issue before 
trying to tackle it. That way we can avoid doing redundant work.

Please check the closed issues for duplicates before creating a new issue (particularly those closed as not planned).

Generally, the following is the order I would prioritize issues based on their tags
(you, of course, can choose to ignore this completely, but if there's a merge conflict
the changes that adress the highest priority issue will be merged before yours):

These are the main categories:  
1) `bug`
2) `enhancement`

Bug fixes are always prioritized over new features.

These labels will act as tiebreakers:  
* `accessibility` - increases priority
* `wishlist` - decreases priority

You are free to remove the `wishlist` label from any issue to signal that a member of the community wants that feature.
